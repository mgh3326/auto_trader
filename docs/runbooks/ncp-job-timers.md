# NCP job timers

This runbook moves only the safe, static-argv part of the 2026-09-04 Prefect
class-B inventory to NCP `systemd` timers. It does not change, pause, or delete
a Prefect deployment. It does not access NCP during development.

## Contract

`ops/ncp/bin/at-job.sh` reads only `/root/at-run/deployed-digest`, which the
pull deploy writes after the blue/green API health check. It rejects anything
other than `ghcr.io/mgh3326/auto_trader@sha256:…` and has no tag fallback. It
does not inspect an `at-api` container. Each service explicitly sets
`AT_RUNTIME_ENV_FILE=/root/at-secrets/.env.api`; the wrapper has no default and
passes exactly that one file to Docker.

The wrapper holds a non-blocking `flock` for the first module, preserves each
child exit code (including timeout), and uses the first nonzero code as the
multi-step process result. Legacy one-step callers still emit exactly one final
JSON summary with `module`, `rc`, `elapsed_s`, and `image_digest`. A duplicate
exits `75`; an unresolved/non-digest deployed image or missing runtime env file
exits `78`.

### Runtime commit gate

A service that declares `AT_JOB_COMMIT_ENV=<KEY>` gets a conditional final
`--commit` token. The key is uppercase-identifier validated. The wrapper first
uses the process environment even when its value is empty; only when absent it
reads the first nonblank, non-comment `KEY=` entry from `AT_RUNTIME_ENV_FILE`.
It trims whitespace, then outer double quotes and outer single quotes, and
accepts only `1`, `true`, `yes`, or `on` case-insensitively. Missing data is
false. The runtime file is read line by line, never `source`d or dot-loaded, and
neither its gate value nor any other value is emitted. Gate summaries add only
the boolean decision and the gate key name.

### Sequential steps

`AT_JOB_STEPS=N` makes a service argv an exact sequence separated by the fixed
`--at-job-step` sentinel. The wrapper rejects a missing/mismatched count and
validates each module and timeout independently. It holds the first-module lock
once, executes every step even after a failure, emits a per-step JSON summary,
then emits the aggregate `steps_total` and `steps_failed` line. This preserves
Prefect's Toss symbol-master list-comprehension behavior: a KR failure does not
prevent the US attempt, but the first nonzero result becomes the unit result.

### Crypto insight equivalence

`scripts/build_crypto_insight_snapshots.py` is frozen verbatim from Prefect's
`RUNNER_CODE`, including its leading newline. The golden records its SHA-256,
and both the checker and test assert that exact file hash. The frozen code has
no `__file__` or `sys.argv` reference, so switching from Python `-c` to its
module entry changes neither of the two observable values that differ between
those invocation forms. Do not format this provenance input.

The observed upstream Docker behavior is intentionally preserved: Prefect puts
`CRYPTO_INSIGHT_*` in its Docker-process environment but does not project it to
the container with `-e`. Consequently this timer runs commit-disabled today.
That is a separate upstream follow-up candidate, not a migration fix.

`tests/fixtures/ncp_job_timers_prefect_argv.json` is generated by the real
Prefect helper. The generator captures gate-off/on argv, Toss's two independent
steps, and crypto insight's `-c` source. Regenerate only with:

```bash
ROBIN_PREFECT_REPO=/Users/mgh3326/services/prefect \
  uv run python -m scripts.ncp_job_timers_golden --write
```

`--check` makes no Prefect/NCP API call and reports a token diff if the fixture
drifts. `scripts/ncp_job_timers_check.py` parses every checked-in `job-*` pair
and proves exact environment, ExecStart, timeout, five next KST occurrences,
no-catchup/no-jitter, and duplicate-schedule rules. Duplicate detection keys on
both occurrence times and derived ExecStart argv: crypto screener and crypto
insight legitimately share a Prefect cron, whereas a copied same-cron/same-argv
unit remains rejected. `--check-cutover` is read-only and reads every named
deployment plus every local timer; its `network calls: N` equals the number of
checked timer jobs.

## Cutover (operator-owned)

For each included unit, do not batch or overlap changes: `Prefect pause →
daemon-reload → enable --now → --check-cutover → first execution rc=0`. Pause
only the matching deployment, and do not enable a timer until the pause has
completed. The checker must be green immediately after enabling and before
waiting for execution. Rollback is the inverse for the same single unit:
disable its timer, then unpause the matching Prefect deployment.

Use this weakest-write-first sequence, recording the named write surface/gate on
the operator change record:

1. `job-crypto-invest-insight-snapshots` — `crypto_insight_snapshots`; observed
   upstream absent container projection keeps commit disabled.
2. `job-toss-warnings-sync` — `kr_stock_warnings`; no additional timer gate.
3. `job-toss-symbol-master-sync` — `kr_symbol_universe`, `us_symbol_universe`,
   and `market_valuation_snapshots`; fixed `--commit`. **Operator approval
   required. Prefect's Discord failure alert (`toss_symbol_master_sync.py:36-50`)
   is not migrated — this unit's failures are observed only through systemd unit
   state and the final JSON summary.**
4. `job-crypto-invest-screener-snapshots` — `invest_crypto_screener_snapshots`;
   `INVEST_SCREENER_SNAPSHOTS_COMMIT_ENABLED` gate.
5. `job-kr-fundamentals-snapshots` — `invest_kr_fundamentals_snapshots`;
   `INVEST_SCREENER_SNAPSHOTS_COMMIT_ENABLED` gate.
6. `job-us-market-valuation-snapshots` — `market_valuation_snapshots`;
   `MARKET_VALUATION_SNAPSHOTS_COMMIT_ENABLED` gate.
7. `job-us-fundamentals-snapshots` — `financial_fundamentals_snapshots`;
   `MARKET_VALUATION_SNAPSHOTS_COMMIT_ENABLED` gate.
8. `job-us-invest-screener-snapshots` — `invest_screener_snapshots`; existing
   explicit `--commit` contract.
9. `job-kr-investor-flow-snapshots` — `investor_flow_snapshots`; existing
   explicit `--commit` contract.

Do not change job argv, image pinning, gates, host policy, or a broker execution
surface as part of a cutover or rollback.

## Prefect retirement roadmap (target: end of September)

- Remaining class B: move only after each flow's complete argv/env/timeout and
  notification contract is captured by a comparable golden.
- Class C: move only when interval/manual or host-specific behavior has a
  separately approved systemd design and tests.
- Class D: retain until their orchestration/notification state machine has a
  durable non-Prefect owner.
- Class E: retain or retire only after the owning operator confirms it is unused.
- `docs/runbooks/prefect-to-postuntil.md` is planned in PR #2040; do not treat it
  as a document present on `main` yet.
