# q2_{kr,us}.csv, q2_{kr,us}_distribution.csv — 앵커 분할 — 방법

대상: `toss_orders.json` 의 LIMIT BUY — 미체결(`CANCELED`/`REJECTED`, 체결 0; Toss 는 정규장 DAY 만료를 15:34 `REJECTED` 로 기록) **137건** + 체결 **5건**(비교군; 6번째 체결은 MARKET 이라 지정가가 없어 제외). crypto 는 입력에 주문이 없다(`q2_crypto.csv`).

## 주문 수명·저가
- 수명 = `[ordered_at, canceled_at | filled_at]`. 주문 세션 = 정규장이 수명과 겹치는 일봉.
- KR 은 KRX 정규장 데이터만 있다(NXT 15:30–20:00·KRX 애프터 없음). 수명이 정규장과 전혀 안 겹치는 주문(NXT 전용)은 수명 가격이 없어 **Q2 에서만** 제외한다(`q2_missing = no_regular_session_overlap`, KR 16건, `q2_q3_coverage.csv` 의 `q3_only:…`). Q3 에는 남는다.
- 분할 이벤트가 주문일 이후에 있으면 제외(`split_after_order`) — yfinance 분할 조정가와 원 주문가가 비교 불가.

## 기준가(“주문 시점 현재가”)
주문 시각을 포함한 60분봉의 시가. 정규장 밖 주문은 그 세션 첫 60분봉 시가, 60분봉이 없으면 세션 일봉 시가(`reference_basis`).

## 변형 (`scheme`)
- `actual_anchor_100`: 실제 주문(예산 100% 를 실제 지정가에).
- `split_20_ref-0.5pct_80_anchor`: 예산 20% 를 `tick_floor(기준가 × 0.995)`, 80% 를 실제 지정가에. 예산 = 실제 주문 `가격 × 수량`(제안 export 상 rung 1개 = 승인 notional). **소수 주 이상화**: 수량 < 5 이면 정수 주로 20/80 분할이 불가능 — `n_qty_lt_5_split_not_whole_shares` 로 표기.

## 체결 가정 (`scenario`) — touch 와 fill 구분
| | 저가 창 | 체결 규칙 |
|---|---|---|
| optimistic | 수명과 **겹치는** 모든 60분봉 | 저가 ≤ 지정가 (touch) |
| conservative | 수명 안에 **완전히 들어간** 60분봉만 | 저가 ≤ 지정가 − 1틱 (trade-through; 지정가 큐가 확실히 소진) |
큐 거래량 근사는 쓰지 않았다(호가별 거래량 데이터 없음). 비교군 5건 검증: optimistic 5/5 체결 재현, conservative 0/5 — 두 가정이 실제를 양쪽에서 감싼다.

## 지표
- `fill_rate`: 한 다리라도 체결된 주문 비율(Wilson + 종목 군집). `filled_notional_ratio` = Σ(체결된 예산 비중 × 예산) / Σ예산, CI = 주문 단위 bootstrap.
- 수익: 체결 다리의 notional 가중, 매수가 = 각 다리 지정가, 수명 마지막 세션 = day 0, day+5/+20 종가.
- `_distribution`: 미체결 주문의 (수명 저가 / 지정가 − 1) 분위수(보수 창, 그리고 `low_incl` = 낙관 창), (지정가 / 기준가 − 1) 분위수.
